# 0002: v0.1 product defaults

Date: 2026-11-08
Status: accepted

## Context

Planning v0.1 raised product questions that the project rules either left open or pulled in
different directions. The founder accepted these recommendations on 2026-11-08.

## Options and decision

| Question | Decision | Main alternative rejected |
| --- | --- | --- |
| Auth on localhost | Follow the project rules (CONTRIBUTING.md, secure defaults): an API key is optional on `127.0.0.1` and required for any other bind. `doctor --security` warns that browsers and local processes can reach an unauthenticated localhost server. `mlx_lm.server` has no API-key support, so MLX refuses non-localhost binds in v0.1 (superseded by [ADR 0009](0009-security-defaults-proxy-and-doctor.md): the Brasskey proxy checks keys for every engine, MLX included). | Auth on everywhere, even on localhost: needs a proxy for MLX and adds friction to the first run |
| Engine install | Detect engines and print the exact install command. Offer an isolated, pinned `uvx` launch for MLX (mlx-lm) and GuideLLM after confirmation. vLLM and SGLang: pinned Docker image or pip hint. llama.cpp: `brew install llama.cpp` hint. | `run` installs engines itself (large, platform-specific, risky) |
| Default model | A quick first run: the best catalog model that fits with at least 25% memory headroom and a download of about 5 GB or less; bigger options that fit are listed. | The biggest model that fits (slow first download) |
| Plain `brasskey doctor` | Shows hardware and detected engines (bug reports, environment checks). `--security` runs the security checks. | Only `--security` |
| Server lifecycle | Foreground; Ctrl-C stops cleanly; a state file lets `doctor` find running servers. No `stop`/`ps` commands in v0.1. | Background daemon |
| Lock files | Nothing is written to the current folder unless `--save` is passed or a `brasskey.yaml` already exists; `run` in a folder with `brasskey.lock` replays it. | Always write files to the working directory |
| Platforms | macOS (Apple Silicon; Intel Macs get CPU llama.cpp) and Linux. Windows through WSL2 only. | Native Windows |
| Install channels | `pip` / `uv tool install`. Script, brew, Docker, the website sample report and playground are release preparation outside these milestones. | Every channel in v0.1, including script, brew and Docker |
| Repository home | `https://github.com/Prcept-AI/brasskey` (the company organization). Also claim `brasskey-ai` to protect the name; GitHub redirects if the repo moves later. | `brasskey-ai/brasskey` first |
| Contributions | Apache-style CLA via a bot. No DCO. Outside pull requests wait until the CLA bot is live. | DCO sign-off as an interim |
| Contacts | praveen92y@gmail.com for security, conduct and trademark reports until a project domain exists. | — |

## Consequences

- `doctor --security` must include the localhost-without-auth warning and the MLX bind rule
  (built in milestone f; the MLX rule became the proxy, see ADR 0009).
- The catalog needs a "quick first run" tier and download-size data (milestone c).
- The CLA text needs drafting (from the Apache ICLA/CCLA, attorney-reviewed) and a bot set up
  before the first outside contribution, as part of release preparation.
- Update the contact addresses in SECURITY.md, CODE_OF_CONDUCT.md and TRADEMARKS.md once a
  project domain (brasskey.ai) is secured.
